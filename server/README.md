# Заявки с сайта в Telegram

## Подключение на Sites

Обработчик уже входит в сборку сайта: `POST /api/request`. Отдельный аккаунт Cloudflare не нужен. `server/site-worker.js` отдаёт опубликованную страницу и передаёт заявку в `server/telegram-worker.js`.

1. Создайте отдельного бота через [@BotFather](https://t.me/BotFather), команда `/newbot`. Сохраните токен вне исходников и переписки.
2. Анастасия должна открыть бота со своего аккаунта, нажать **Start** и отправить согласованное контрольное слово.
3. Получите ID **её личного чата** по сообщению с этим контрольным словом через `getUpdates`. Не выбирайте первый попавшийся чат. Username вместо числового ID для личного чата не подходит.
4. Через инструмент секретов Sites сохраните `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` как секреты текущего сайта. Не помещайте значения в `.openai/hosting.json`, Git или браузерный код.
5. Откройте сайт заново и отправьте заявку с вымышленными данными и словом «Тест». Убедитесь, что сообщение появилось в чате Анастасии и сайт показал подтверждение.

До настройки обоих секретов форма открывает прежний черновик Telegram. После настройки сервер включает прямую отправку в HTML страницы. Страница не кешируется, поэтому изменение конфигурации применяется при её следующем открытии. Сервер не отправляет токен или ID чата в браузер.

Форма блокирует повторное нажатие во время отправки и очищает поля только после подтверждения Telegram. При ошибке или таймауте текст остаётся, появляется ссылка для ручной отправки. Отдельная база заявок не ведётся. Получатель определяется только настройками сервера.

В Sites действует ограничение пяти запросов за минуту на IP в пределах экземпляра Worker. Это не общая долговременная квота для всех экземпляров. Отдельный Cloudflare Worker использует нативную привязку `REQUEST_LIMIT` из `wrangler.jsonc`.

Справка Telegram: [создание бота](https://core.telegram.org/bots/features#creating-a-new-bot), [getUpdates](https://core.telegram.org/bots/api#getupdates), [sendMessage](https://core.telegram.org/bots/api#sendmessage). Для нового бота без webhook обновления доступны в течение 24 часов.

## Сборка и проверки

`npm run build` создаёт статический `out/`, затем автономный Worker в `dist/server/index.js`. В Worker включаются только файлы `out/`. Старый `dist/` — генерируемый результат сборки — заменяется после проверки, что он находится внутри текущего checkout и не является ссылкой. Исторические исходники остаются в `src/reference` и Git.

`npm run check` проверяет страницу и побайтовое совпадение всех ресурсов Worker со статической сборкой. `npm test` проверяет доставку с подменённым API Telegram, ошибки, проверку полей, ограничение повторов и поведение формы. Автоматические проверки не отправляют настоящие сообщения.

## Статическая публикация на GitHub Pages

`out/` сохраняет ручной Telegram-сценарий: GitHub Pages не исполняет серверный код. Автоматическую доставку на этом адресе нужно подключать отдельно к публичному обработчику. Не используйте закрытый адрес Sites как API для анонимных посетителей GitHub Pages.

Для отдельного Cloudflare Worker остаются `telegram-worker.js` и `wrangler.jsonc`. Его секреты: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`; разрешённые дополнительные origins задаются через `SITE_ORIGINS`. На финальной странице адрес публичного обработчика задаётся атрибутом `data-request-endpoint` у `<body>`; этот адрес не должен содержать секретов.
